# BigO Inspector

BigO Inspector — учебное расширение VS Code для ориентировочной оценки сложности функций в проектах на C++. Оно получает AST от Clang, ищет циклы и некоторые шаблоны рекурсии, а затем показывает оценки Big O, объяснения со строками кода и график роста.

> Это статический эвристический анализатор. Его оценка помогает заметить распространённые шаблоны, но не является формальным доказательством сложности программы.

## Возможности

- Анализ файлов `.cc`, `.cpp`, `.cxx` и заголовков `.h`, `.hh`, `.hpp`, `.hxx` в открытой папке.
- Оценка циклов и поддерживаемых шаблонов прямой рекурсии.
- Учёт вызовов функций, определения которых найдены в проекте.
- Таблица оценок по функциям, объяснения и переход к строке исходника.
- Сводка с наибольшей распознанной оценкой и график типовых кривых роста.

## Требования

- VS Code 1.85 или новее.
- Node.js 18 или новее.
- `clang++`, доступный через `PATH`.

Проверьте, что компилятор доступен, командой `clang++ --version`. Если проект использует нестандартные параметры сборки или пути к заголовкам, положите `compile_commands.json` в корень проекта. Иначе расширение запускает Clang со стандартом C++17. Путь к компилятору и стандарт можно изменить в настройках `bigoInspector.clangPath` и `bigoInspector.standard`.

## Запуск из исходников

1. Откройте папку проекта в VS Code.
2. Установите зависимости: `npm install`.
3. Соберите расширение: `npm run build`.
4. Запустите тесты: `npm test`.
5. Нажмите `F5`. Откроется отдельное окно Extension Development Host.
6. Чтобы проверить свой код, в этом отдельном окне выберите **File → Open Folder…** и укажите папку своего C++ проекта.
7. Нажмите `Ctrl+Shift+P`, запустите **BigO Inspector: Analyze C++ Project** и дождитесь отчёта.

Расширение анализирует C++ файлы в выбранной папке и её подпапках. Вставлять код в окно отчёта не нужно. Если PowerShell блокирует команду `npm`, выполните соответствующую команду через `npm.cmd`, например `npm.cmd test`.

## Установка готового расширения

Скачайте [BigO Inspector VSIX](https://github.com/NiksGH/Lab3_ISRPO/blob/main/bigo-inspector-0.1.0.vsix). В VS Code откройте палитру команд (`Ctrl+Shift+P`), выберите **Extensions: Install from VSIX…** и укажите скачанный файл. После установки откройте папку C++ проекта и запустите **BigO Inspector: Analyze C++ Project** из палитры команд.

## Правила оценивания

| Найденный шаблон | Оценка |
| --- | --- |
| Нет циклов и рекурсивных вызовов | `O(1)` |
| Цикл с постоянной числовой границей, например `i < 10` | `O(1)` |
| Цикл с постоянным шагом к переменной границе | `O(n)` |
| Цикл с геометрическим изменением счётчика | `O(log n)` |
| Два вложенных линейных цикла | `O(n²)` |
| Линейный цикл с вложенным логарифмическим циклом | `O(n log n)` |
| Последовательные циклы | Максимум оценок этих циклов |
| Один прямой рекурсивный вызов с аргументом `n - c` и базовым случаем | `O(n)` |
| Один прямой рекурсивный вызов с аргументом `n / c` и базовым случаем | `O(log n)` |
| Два вызова с `n - c`, как в наивном Фибоначчи | `O(2ⁿ)` |
| Два вызова с `n / 2` и линейной работой на шаге | `O(n log n)` |
| Нераспознанный цикл или шаблон рекурсии | `O(?)` |

Вложенные циклы оцениваются по одной цепочке вложенности; последовательные циклы не перемножаются. Стоимость вызова функции из проекта учитывается, в том числе если вызов находится внутри цикла. Взаимная рекурсия и сложные рекуррентные соотношения пока не решаются.

## Архитектура

```text
Команда VS Code
  └── src/extension.ts — находит C++ файлы и показывает отчёт
       ├── src/clang.ts — запускает clang++ и получает AST в JSON
       ├── src/analysis.ts — оценивает циклы, вызовы и шаблоны рекурсии
       └── media/report.js — рисует таблицу, сводку и график в Webview
```

Каждый файл анализируется отдельно. Ошибка компиляции одного файла показывается в отчёте и не останавливает анализ остальных. Компилятор запускается в режиме проверки синтаксиса, исполняемый файл программы не создаётся.

## Проверки

`npm test` собирает TypeScript и запускает тесты Node.js. Они проверяют оценки циклов, последовательные и вложенные циклы, вызовы функций между файлами, поддерживаемые шаблоны рекурсии и неизвестные случаи.

## Ограничения

- Анализатор распознаёт ограниченный набор AST шаблонов. Для непонятного условия, шага или рекурсии он показывает `O(?)`.
- Стоимость библиотечных функций и функций вне открытого проекта не анализируется.
- Не моделируются разные размеры входа, распределение данных и ранние выходы.
- Для QuickSort сложность зависит от выбора опорного элемента и размеров разбиений; если анализатор не распознал разбиение, он может показать `O(?)`.
- График иллюстрирует типовые кривые роста и не измеряет фактическое время выполнения.

## Кратко о защите

Clang строит AST исходного C++ кода, поэтому расширение работает со структурами языка, а не ищет циклы простыми текстовыми шаблонами. Анализатор применяет небольшой набор правил к AST и связывает оценку с функцией и строками кода. Поскольку поддерживаются не все конструкции и рекуррентные соотношения, неизвестные случаи явно помечаются `O(?)`.
